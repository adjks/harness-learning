# Weekly Harness Notes - 2026-07-17

## 本周资料

- [AI Harness Engineering: A Runtime Substrate for Foundation-Model Software Agents](https://arxiv.org/abs/2605.13357)：提出把 harness 看作 foundation-model 软件工程代理的运行时底座。
- [Agentic Harness Engineering](https://arxiv.org/abs/2604.25850)：强调 harness 组件、经验和决策都需要可观测，harness 本身可以迭代优化。
- [Code as Agent Harness](https://arxiv.org/abs/2605.18747)：把代码视为 agent 推理、行动、环境建模和执行验证的操作性底座。
- [SWE-Bench Pro](https://arxiv.org/abs/2509.16941)：用更长周期、更企业化的软件工程任务测试 agent 能力，提醒我们不能只用短任务评价工作流。

## 本周实践点

把“让 AI 做任务”改成“让 AI 运行在一个小 harness 里”：

1. 先写任务契约。
2. 再收集上下文。
3. 执行时记录关键动作。
4. 完成后保存验证证据。
5. 复盘失败归因和下次要改的规则。

## 对个人工作流的影响

最小可行 harness 不需要复杂系统。一个 Markdown 任务契约、一个验证清单、一个复盘模板，就能显著改善个人 AI 协作质量。

## 待验证

- 推断：对个人开发者而言，最先值得自动化的不是多代理编排，而是任务契约和验证证据记录。
- 待验证：每周自动周报是否会产生足够高质量的行动项，需要连续运行 4 周后复盘。

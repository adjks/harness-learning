# Weekly Harness Notes - 2026-07-17

## 本周主题

这周重新校准仓库方向：重点不是记录我自己的 AI 使用流水账，而是收集网络上大家如何 **Harness 驾驭 Agent** 的实践，再提炼为可迁移到个人工作流的模式。

## 本周资料

- [Claude Code best practices](https://code.claude.com/docs/en/best-practices)：强调先探索、再计划、再实现、再提交；复杂任务要把 planning 和 coding 分开。
- [Claude Code power user tips](https://support.claude.com/en/articles/14554000-claude-code-power-user-tips)：把 verification 放在第一位，认为给 agent 可执行反馈回路是最重要的质量提升手段。
- [Claude Code common developer use cases](https://support.claude.com/en/articles/14553517-claude-code-common-developer-use-cases)：展示 coding agent 在修测试、理解代码、查找行为、triage 错误、refactor with plan、写测试、review PR 等场景中的使用方式。
- [OpenAI: Harness engineering](https://openai.com/index/harness-engineering/)：提出 “Humans steer. Agents execute.”，强调人类设计环境、指定意图、建立反馈回路。
- [VS Code: The Coding Harness Behind GitHub Copilot](https://code.visualstudio.com/blogs/2026/05/15/agent-harnesses-github-copilot-vscode)：把 coding harness 描述为组装上下文、暴露工具、运行 agent loop、解释工具调用的层。
- [Anthropic: A harness for every task](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code)：介绍 dynamic workflows，把可重复任务封装为可运行流程。
- [AgentWay: Claude Code workflows](https://agentway.dev/en/claudecode/workflows)：给出 feature development 的 Explore -> Implement -> Test -> Commit 工作流示例。

## 本周提炼的实用模式

### 1. Explore -> Plan -> Implement -> Verify

复杂任务先让 agent 只读探索，不要直接实现。让它输出计划、文件范围、风险和验证方式，再进入执行。

### 2. Verification first

实践资料高度一致：agent 的可靠性来自反馈回路。测试命令、浏览器检查、lint、端到端脚本、事实核查清单，都可以作为 harness 的验证器。

### 3. Humans steer, agents execute

人的工作不是逐行写代码，而是给出意图、边界、环境和验收标准。agent 负责执行，人的重点是审计划、审证据、审风险。

### 4. Isolate, scope, approve

高自治 agent 需要隔离环境、有限权限和人工批准。个人使用时可以对应为：新分支/worktree、明确禁止事项、高风险操作前确认。

### 5. Reusable workflows

重复任务不要每次重新 prompt。把周报、PR 审查、资料核查、前端验收、发布检查做成固定 workflow。

## 对个人工作流的启发

下一步值得把个人使用 agent 的入口改成一个固定问题组：

- 这次任务是否需要先探索？
- 完成标准是什么？
- agent 可以运行哪些验证？
- 哪些动作必须先确认？
- 最后要留下什么证据？

这不是记录个人实践，而是把网络实践转成个人可用的 harness checklist。
